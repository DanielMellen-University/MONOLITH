# Start menu type-ahead filter (7.6)

While the Start menu is open, typing filters rows by case-insensitive substring on the Start menu label (`AppRegistry`-driven). Closing the menu clears the filter.

## Behavior

- **Type**: `SDL_TEXTINPUT` appends complete UTF-8 codepoints to `m_startMenuFilter` (shell-owned; does not reach the suspended client), up to 64 bytes. This is longer than every current actionable label, so the cap does not hide a match.
- **Backspace**: edits the filter (UTF-8 aware pop).
- **Escape**: clears a non-empty filter first; otherwise closes the menu. Matching key-up stays shell-owned either way.
- **Arrow / Enter**: navigate and activate the filtered actionable hit list (category headers stay action `-1`, not hit-testable).
- **Chrome**: active filter string is drawn as a small muted line under the Monolith header (header grows from 22 to 36 logical px while filtered).

## Wire

- `filterStartMenuRows` / `startMenuLabelMatches` in `StartMenuFilter.hpp`
- `appendStartMenuFilterInput` enforces the UTF-8 byte cap
- `wm_start_menu_rows.inc` builds from the filtered row list (shared by render and `ensureStartMenuHitTargets`)
- Input in `tryHandleShellHotkeys` (`wm_body_08c.inc`); chrome in `wm_body_03a.inc`
- Filter-aware header height applied at Start menu render/hit call sites so layout stays aligned
- Filter state declared on `WindowManager` (hpp private section or `WindowManager_private.inc`)
